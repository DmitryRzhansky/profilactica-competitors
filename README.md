# Генератор GEO-запросов

Скрипт собирает минимальный пул запросов `услуга + GEO` для проверки спроса в Wordstat или Арсенкине. Он не строит семантическое ядро, не добавляет коммерческие хвосты и не запрашивает частотность.

Базовый шаблон:

```text
{маска} {geo}
```

Для станций метро добавляется вторая строка:

```text
{маска} метро {geo}
```

Названия не склоняются. Из `Королёв` получается `королёв`, а не `в королёве`.

## Запуск

```bash
python generate_geo_queries.py
```

Фильтры:

```bash
python generate_geo_queries.py --service narkolog-na-dom
python generate_geo_queries.py --service reabilitaciya
python generate_geo_queries.py --geo-type metro
python generate_geo_queries.py --geo-type mo
python generate_geo_queries.py --service kapelnica-na-dom --geo-type mo
```

Другие параметры:

- `--input` — master CSV. По умолчанию `profilactica_geo_master_lists.csv`.
- `--output-dir` — каталог результатов. По умолчанию `output/`.

Нужен Python 3.11+. Внешних библиотек нет.

## Откуда берутся GEO

Источник — `profilactica_geo_master_lists.csv`, колонки `geo_type`, `name`, `slug`, `tier`. Исходный файл скрипт не изменяет.

| Тип | Что попадает в запросы |
|---|---|
| `metro` | все станции из CSV |
| `okrug` | все округа из CSV |
| `mo` | все города из CSV |

Для лечения алкоголизма, лечения наркомании и реабилитации берутся только города с `tier=tier-1`. В текущем файле это 30 основных городов МО. Список не строится как первые 30 строк. Если число городов `tier-1` не совпадёт с `mo_limit` в конфигурации, скрипт остановится с ошибкой.

Строки с другим `geo_type` считаются legacy и в запросы не попадают. Отсутствие обязательной колонки, пустое поле и повтор пары `geo_type + slug` тоже останавливают запуск.

## Услуги

Маски и допустимые GEO лежат в `config/services.py`. У одной услуги может быть несколько масок: у реабилитации их три.

| service_id | Маска | metro | okrug | mo |
|---|---|---:|---:|---:|
| narkolog-na-dom | нарколог | 2 запроса | 1 | все города |
| vyvod-iz-zapoya | вывод из запоя | 2 запроса | 1 | все города |
| kapelnica-na-dom | капельница | 2 запроса | 1 | все города |
| kodirovanie | кодирование | 2 запроса | 1 | все города |
| psihiatr-na-dom | психиатр | нет | 1 | все города |
| lechenie-alkogolizma | лечение алкоголизма | нет | нет | tier-1 |
| lechenie-narkomanii | лечение наркомании | нет | нет | tier-1 |
| reabilitaciya | реабилитация зависимых / алкоголиков / наркоманов | нет | нет | tier-1 |

Чтобы добавить ещё одну маску, допишите строку в список `queries`. Генератор менять не нужно.

Автоматически не добавляются цена, стоимость, срочность, «на дом», «клиника», «центр» и другие коммерческие модификаторы. Слово из названия GEO сохраняется: станция «Деловой центр» даёт запрос `нарколог деловой центр`.

## Результаты

Каждый запуск заново собирает файлы в `output/`:

- `geo_queries.csv` — полная таблица. Один и тот же текст может повториться, если это разные услуги или разные GEO.
- `wordstat_queries.txt` — один запрос на строку, без кавычек, операторов и пустых строк. Повтор по правилу `ё = е` остаётся один раз; в тексте сохраняется написание из CSV.
- `queries_<service_id>.txt` — запросы одной услуги. В файле реабилитации три маски идут подряд для каждого города.
- `queries_metro.txt`, `queries_okrug.txt`, `queries_mo.txt` — те же запросы по типу GEO.

Порядок: услуга из конфигурации, затем строка master CSV, затем маски этой услуги. Для метро вариант со словом `метро` стоит сразу после базового запроса.

На текущем master-файле полный прогон даёт 2180 строк CSV: 492 на каждую из четырёх широких услуг, 62 на психиатра, по 30 на лечение алкоголизма и наркомании, 90 на реабилитацию.

В Wordstat уходит 2176 уникальных строк. Четыре повтора — это станция метро Котельники и город Котельники: базовый запрос совпадает. В CSV остаются обе сущности, в `wordstat_queries.txt` — одна строка. Вариант `нарколог метро котельники` сохраняется отдельно.
